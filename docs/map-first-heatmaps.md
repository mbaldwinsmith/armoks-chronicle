# Map-first atlas and population heatmaps

The atlas puts the landscape above comparative statistics. Main view/colour/zoom and heat controls precede the canvas; secondary map controls, legends and statistics follow. A Historical Filters & Statistics button opens and scrolls to the historical controls. Rivers start off. With no explicit view URL, supported maps attempt the native WebGL renderer; unsupported graphics or maps beyond its 129 × 129 budget retain the explained flat fallback. Explicit flat/Canvas-relief URLs still work.

Heatmaps start enabled. The default is total site population when there is a verified settlement report association, otherwise recorded events. The same bounded tile overlay array goes to flat Canvas, Raised Relief and WebGL. Values use logarithmic intensity, with scale, mapped measurement sum, unknown location and excluded-count disclosures. Selecting a tile shows its measurement. Heat visibility, metric, report and group survive route/source-return links.

Population uses the existing report reader and its format contract in `population-and-world-reports.md`. It requires a saved matching `world_sites_and_pops.txt`, exact settlement ID/name association and filename prefix, supported encoding and complete matching indexes. It does not estimate population from historical-figure counts. The existing four-file/32 MB combined report budgets apply; world-history identity checks remain active. Report limits or uncertain legacy decoding withhold unsafe associations. Matching sites must have usable CSV coordinates to draw.

One selected report is used at a time. Multiple snapshots are never summed. Total population includes all numeric site report groups, including animals; partial, duplicate, unparsed or Unnumbered totals are omitted. Species/group options retain report labels, without inferring creature tokens from plural English names. An absent group or Unnumbered entry is unknown rather than zero. Co-located settlements aggregate their valid measurements into one tile. Population stays an export snapshot, unaffected by historical year/event, comparison-group or settlement faction filters. File dates are clues only.

Named Death Victims uses explicit `hf died` victim fields (`hfid` / `victim_hf`), matching existing warfare semantics. Each identified victim counts once in the selected event scope. Victims with conflicting mapped locations are excluded; unidentified victims and squad reports are not added to the count. Attack events include `attacked site` and `field battle`; wound events use `hf wounded`. These and Recorded Events follow the historical event scope, including year/type/comparison filters. Counts describe available records, not true mortality or risk.

The implementation reuses the previously verified DFHack text-report contract and report association/decoding functions; it adds no export-schema guesses, runtime dependency, network upload, database migration or deployment build step. Existing archives work immediately if the matching report was included at import. Archives lacking the report can still use event heatmaps.
